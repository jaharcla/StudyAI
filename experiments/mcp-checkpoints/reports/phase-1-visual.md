### Concrete finding about the checkpoint

When an arrow is created with `startElementId`/`endElementId`, the upstream CLI **auto-routes and discards supplied waypoints** — the first correction produced a straight vertical arrow despite a 4-point path. Explicit routing requires omitting the bindings and supplying `points`. This is a reproducible behavior of the pinned version and is relevant to any adaptation of its arrow-binding approach.

## StudyAI bridge — not run

Reasons, verified in this worktree:
- no `.env` (only `.env.example`), so no model credentials for artifact generation;
- no `node_modules` (root dependency tree not installed);
- no `data/studyai.sqlite`.

Therefore conditions A and B were **not** executed against StudyAI, and no StudyAI structural/visual/defect/correction metrics are reported. Tokens, tool calls per successful artifact and time are **not measured** for either system: the upstream elements were authored deterministically by hand rather than generated by a model, so any token figure would be fabricated.
