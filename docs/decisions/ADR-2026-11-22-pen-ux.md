# ADR-2026-11-22 — Pen-on-paper UX at the StudyAI capture boundary

## Context

StudyAI needs four pen behaviours: pressure/velocity smoothing, palm rejection,
scratch-out-to-erase, circle-to-select, and double-tap handwriting-to-LaTeX behind
an approval gate. All ink lives in the installed `@quickdrawjs/react@0.1.0` /
`@quickdrawjs/core@0.1.0` packages. StudyAI must not mutate `canvases.document`
directly, and must not create a second board-interpretation authority.

## What the installed package actually provides (authoritative source)

Cited from the installed package, not from memory or the repo-root reference zip:

- `node_modules/@quickdrawjs/core/src/freehand.js:9` — `strokeOutline(pts, opts)`
  already performs exponential streamline (velocity smoothing, lines 17–24),
  velocity-simulated pressure (lines 26–40), a thinning pressure curve (line 40)
  and tip taper (lines 42–50). Public type at
  `node_modules/@quickdrawjs/core/types/index.d.ts:127-133`.
- `node_modules/@quickdrawjs/core/src/shapes.js:305` — render calls
  `strokeOutline(p.pts, { size: INK_SIZES[p.size], simulate: !p.isPen })`.
- `node_modules/@quickdrawjs/core/src/editor.js:645-680` — `Editor` owns stroke
  geometry (`shape.props.pts`) internally in `_beginDraw` / `_extendDraw`;
  pressure is read straight from `e.pressure`.
- `node_modules/@quickdrawjs/core/src/editor.js:44-54,271-286,451-476,513-515,579`
  and `types/index.d.ts:197,242` — `Editor.setPenMode(on)` plus the `penmode`
  event already gate touch input once a stylus is seen; auto-arm is once-only so
  mouse users are unaffected.
- `node_modules/@quickdrawjs/core/types/index.d.ts:166,247,257,116` — documented
  `Store.remove`, `Editor.setSelection`, `Editor.hitTest`, `pageBounds`.
- `node_modules/@quickdrawjs/react/types/index.d.ts:38-40` — documented
  `onMount` / `onChange` / `onSelectionChange` callbacks;
  `src/index.js:107-112` shows `onChange` is the store listener and
  `onSelectionChange` mirrors `editor.selection`.

There is **no** documented public hook to transform a raw pointer sample before
the editor writes `props.pts`. Changing that would require editing
`editor.js` inside `node_modules` (out of scope). Dispatching rewritten synthetic
pointer events to fight the library's own listeners would bypass its gesture
batching and history — the "hack around revision rules" the task forbids.

## Decision

Do not modify the installed library and do not rewrite DOM pointer events. Build
one small StudyAI-owned module, `src/canvas/pen-input.ts`, that:

1. smooths the **captured pressure** of a live ink shape through the documented
   `Store.update` API inside the existing `onChange` callback. Updates land in
   Quickdraw's own `beginBatch`/`endBatch` gesture window
   (`node_modules/@quickdrawjs/core/src/store.js:99-120,170-182`), so one stroke
   remains one undo step and persistence stays on `server/canvas-persistence`.
   Render-time streamline/taper/pressure-curve in `strokeOutline` is reused as-is
   and is not duplicated.
2. recognises scratch/circle/double-tap gestures from StudyAI's own capture-phase
   pointer trail in `CanvasStudio.tsx` and routes outcomes through documented
   `Store.remove`, `Editor.setSelection` and the existing analysis/proposal UI.
3. persists the palm-rejection toggle in `localStorage` and drives
   `Editor.setPenMode` only through the public API.

Alternatives rejected: patching `node_modules/@quickdrawjs` (forbidden; breaks on
reinstall), synthetic pointer-event rewriting (breaks gesture history), a new
`ScientificObject` kind (banned by the six-part rule and the task scope), and a
third scene-interpretation path (banned by the canvas invariants).

## Limits

No physical stylus is available in this environment. Pressure/pointerType are
exercised with synthetic `PointerEvent`s in Playwright only. Real-device checks
are listed, unclaimed, in `docs/verification/2026-11-22-pen-ux.md`.
